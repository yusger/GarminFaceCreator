# 分阶段实施与验证

每阶段流程：实现及本地构建 → 实现提交 → 指定远程测试环境部署和验证 → 结果提交 → 下一阶段。测试地址和凭据不写入仓库；Temp 继续仅用于本地临时资料。

## 阶段 1：P0-01 保存与冲突恢复

- 实现提交：`7abad50`。
- IndexedDB 在同一个读写事务内比较并递增 storageVersion，与设计 revision 独立；旧项目缺失版本按 0 处理。
- 保存任务串行执行，失败停止自动写入；当前内存设计、导出入口及关闭页面提醒保留。
- 冲突可加载最新、另存独立副本或放弃本次保存；加载前确认，副本需重新生成原生代码，避免沿用旧应用 ID。
- 不依赖 BroadcastChannel，关闭该功能仍保护冲突。存储打开、blocked、事务中止与配额失败均有错误出口。
- 本地：TypeScript/Vite 生产构建通过。
- 远程：已提交产物部署后，`storage.spec.ts` 2 项通过，现有 editor 编辑/撤销/预览/保存/导出回归 1 项通过。
- 浏览器测试使用独立测试上下文，不改写用户浏览器中的项目，不调用付费模型。

## 阶段 2：P0-02 按目标设备编译就绪

- 实现提交：`b3cbba8`。
- capabilities 保留 targets 与聚合 ready，新增 common 和 devices（每个 target 的 ready/reasons）。公共检查包含 SDK、初始化配置、签名密钥和 Java；接口不返回服务器私有路径。
- 前端构建上传前检查当前 target；后端验证 target 后、创建任务和写入工程前检查对应环境，缺失时返回带原因的 503。
- 本地：前端生产构建、.NET Release 构建通过。
- 远程：capabilities API 检查、前端缺失目标拦截 1 项通过；真实 SDK 编译/PRG 下载、失败产物拒绝、取消及路径/DTD 校验通过。
- 远程隔离容器只挂载 Venu 3 设备包：Venu 4 45mm 缺失时 Venu 3 与聚合 ready 仍为 true；缺失目标在排队前返回 503。临时容器已停止，未修改主服务设备包。
- 隔离脚本首次检查遇到启动时连接重置，补就绪重试后通过；脚本见 backend/tests/readiness-isolated.sh（从测试部署目录运行）。

## 阶段 3：P0-03 图片资源链路

- 实现提交：`b8375be`，远程复现后的修复提交：`c289dc6`。
- 修复导入副本沿用 storageVersion 导致误报冲突；副本版本重置为 0，仍生成独立项目/应用身份。
- 网页中文、空格和符号素材名称保留为图层名称，实际图片资源使用 UUID 路径。多图导出/再导入后，生成请求仅含素材路径、不含图片二进制；生成资源 XML、上传路径和源码引用一致。
- 远程实际发现 SDK 无法解析中文 PNG 工程路径（文件已正确上传），因此原生工程非 ASCII 路径在 API 排队前明确拒绝。兼容现有网页自动生成的 ASCII 素材路径，不盲目搬迁已有资源目录。
- 远程多张 PNG + 位图字体真实编译/PRG 下载通过；中文原生路径拒绝场景通过。
- 本机 SDK 模拟器加载远程产物，确认红/蓝两张位图及白色位图字体测试字形实际显示，截图见 [资源验证](screenshots/resource-validation.png)。模拟器已关闭；未据此声称完成真机验收。
- 最终远程浏览器回归 6 项通过：ClownWatch、SkyRing、fine-o-clock 独立参考副本真实编译，图片导出再导入/编译，原子保存冲突，配额失败重试。
