# 实际内容来源与许可分发

参考包、固定原生模板、独立生成代码、字体和图标分别记录来源，不因为存为 JSON 或从工具输出就统一改变其许可。

- 参考目录共用一份来源登记；每次 build 计算当前参考包字节 SHA-256，保留许可文件和源地址。三个已有包的原始上游提交没有被记录，明确标记未知，不从近似代码或当前 HEAD 反推。SkyRing 的许可尚未确认；fine-o-clock 保留 README/GPLv3+ 与 LICENCE/LGPLv3 的矛盾。已有用户副本不重写，新参考必须给出固定上游提交和已核查许可。
- 导出携带实际 Monkey C 源码、资源、来源关联、当前包指纹、代码来源/AI patch、所用图标原图及完整许可。design-source.json 只记录当前导出设计，不含图像字节或历史；PNG/字体资源仍在工程中。完整浏览器工作区恢复应使用项目 JSON 备份。
- 观察到固定生成模板标记时，按文件记录模板版本和其源码来源许可证，附仓库 GPLv3+、实际原生源码和可匹配的源码上下文快照。快照是说明复制模板的 TypeScript 源码，不是完整工具构建，也不参与 SDK 编译；原生 source/resources 已完整包含。旧版本没有可匹配快照就标为不可用，不能以当前代码冒充历史版本。
- 未观察到固定模板且没有参考关联时，不自动附加“整个输出属于 GPL”的结论；独立 AI 内容仍按实际来源判断。模板标记/来源关联是工程溯源证据，不是对每一段代码衍生关系的法律裁决。
- 素材详情展示真实作者、版本及许可；参考卡片展示明确的许可状态和原始文件。没有把许可未确认改写成获得授权，也没有删除上游源码来规避完整工程要求。

固定模板发生实质修改须更新版本。构建前自动生成 reference-notices/provenance.json 和对应 LF 规范化源码快照；第三方原始 SVG 仍保留逐字节原文。build 校验参考身份、必要许可文件和新参考准入条件，部署测试再核对 HTTP 字节哈希。

依据：[GNU FAQ：工具输出](https://www.gnu.org/licenses/gpl-faq.html#GPLOutput)、[输出中的程序内容](https://www.gnu.org/licenses/gpl-faq.html#WhatCaseIsOutputGPL)、[GPLv3 原文](https://www.gnu.org/licenses/gpl-3.0.html)。这里实现来源记录、适用声明与源文件分发流程，不对许可未确认的内容授予缺失的权利，也不提供对全部作品的统一许可判断。
