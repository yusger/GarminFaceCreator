# 时间序列图表控件：交互与数据契约

本文件先于控件实现固化约定。阶段B1开放每日步数、活动距离、总热量；柱状、梯形柱、分段柱。阶段B2随后开放小时心率、折线/面积和独立心电装饰；未实现的组合不得显示为已支持。

图表是一个对象，整体拖动/缩放/复制。属性分为时间范围、数据与统计、图形样式；标题、来源图标、标签、数值、摘要和覆盖计数可开关。每日长度1–7，包含或排除当前日；时间窗口、数据记录数、有效点数分别定义。当前未结束的日使用标记，缺失留空，真实零值保留。常规柱上方/底部不被伪造成真实历史。

B1官方来源：[ActivityMonitor.getHistory](https://developer.garmin.com/connect-iq/api-docs/Toybox/ActivityMonitor.html#getHistory-instance_function)最多7条、最近优先；[History字段](https://developer.garmin.com/connect-iq/api-docs/Toybox/ActivityMonitor/History.html)可缺失，distance为厘米，转换为千米，calories为当日总千卡。按当前设备时区解释startOfDay并按年月日归并；重复日期采用第一条。当天只使用getInfo当前值，历史中的同日记录不累加，当前值不可用则当日缺失。记录不足不补零，也不假定安装前有完整7天。

每日窗口以当地日历日期推进，不用固定86400秒减日期；时区改变会影响旧时间戳的本地归日。历史缓存最长60秒，跨日、时钟回退/跳变及本地时区相位改变时失效；AOD仅使用上次亮屏快照，不新增历史/传感器读取。重启从官方接口重新读取，无本地虚构历史补齐。

统计摘要使用显示点的最新/均值/最大/合计；均值仅按有效点，缺失不作零，且不宣称代表完整覆盖。自动纵轴从0到有效最大值（全零上界1）；固定纵轴保留真实数值、仅裁切绘图范围。目标线是固定设计值，不宣称Garmin自动目标。数值可选k/M紧凑表达。

梯形柱上窄下宽，顶宽比例可调；分段柱可调段数/间隙/暗轨；AOD简化为缓存普通柱。网页历史明确为示意，支持正常/零/缺失/部分/极值，截图元数据保留说明，不能把示意历史当作原生API覆盖证据。

B2小时将按实际经过的小时分桶，平均/最高/最低/末值只用有效心率样本；覆盖依设备与最近开机状态，不承诺7小时齐全。心电装饰不从bpm伪造ECG，不具有医疗含义，必须保留装饰标识；相关控制在实现前禁用。

预算：首批Venu4两尺寸，最多4图表；每图最多7点、16段，过小控件给出生成诊断。原生SDK、真实API缺失/零值运行及测试夹具的绘制对照分别验收；强制AOD夹具不代表真实Sleep事件通过。

实现位置：`frontend/src/charts.ts`统一校验、日历序列与几何；`ChartWidget.tsx`网页绘制；`ChartInspector.tsx`属性；`nativeCharts.ts`原生缓存、读取和绘图。项目Schema37兼容升级36；AI与工程DTO复用嵌套chart白名单。公开发布包v2目前仍按自身版本能力约束，不能仅改项目Schema号就当作包规范升级。

## B2实施约定：小时趋势

小时首批只接心率，长度1–7代表实际经过的小时桶；包含当前桶可选。当前桶用设备本地分钟/秒回退到其起点，旧桶每次减3600秒，不把重复的夏令时墙钟小时合并。原生标签按各桶时间戳的本地小时；重复HH仍是不同时间戳。网页明确示意，固定UTC偏移时不假装重建历史时区规则。

使用SensorHistory.getHeartRateHistory({period:new Time.Duration(8*3600),order:NEWEST_FIRST})，Number不能当秒数。单次最多处理1024条最近样本，按实际when归桶；零/负/非数值/未来样本不计入有效心率。支持桶内均值/最大/最小/末值，摘要合计在小时心率禁用。记录不足留缺失，不保证7小时齐全。覆盖显示有效桶数与实际样本数，预算截断加星号；一条样本不代表完整一小时覆盖。

历史读取在亮屏最多60秒一次；跨小时、时钟回退、时区相位改变失效。AOD只用最后亮屏桶，不再查历史，绘制简化为普通柱。无持续采样、定时唤醒或安装前虚构数据。

每日和小时开放折线/面积。缺失处断开；点、线宽、面积透明度可调。阈值颜色沿用已登记规则，线段使用终点读数的颜色，面积使用相应段颜色；AOD忽略活动阈值色。心电/ECG数据类型仍不开放，不能将bpm折线冒充ECG；Vital现有静态心电装饰与本图表历史独立。
