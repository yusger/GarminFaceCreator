# 整盘主题预设与AI公开操作

项目Schema38沿用ThemeSet.version=1，新增可选 `themes.overrides[themeId].backgroundColor`，仅允许合法现有themeId与十六进制色。未提供的背景覆盖读取对应preset默认色。旧Schema37顺序迁移，身份不变。

解析顺序：主题默认背景→该主题背景覆盖；数值/颜色/装饰仍通过已登记控件controlValues解析，互不污染其他主题。当前主题恢复默认仅清除该主题控件和背景覆盖，不回滚几何编辑，不清除公共或其他主题参数。复制、快照、撤销、导出保留覆盖。

AI对话公开操作：

- `{"type":"theme","action":"select","themeId":"已有ID"}`：切换完整主题。
- `{"type":"theme","action":"reset"}`：恢复当前主题配置默认值。
- `{"type":"background","color":"#112233"}`：修改当前主题背景覆盖；无主题项目修改项目背景。
- `control/update/remove/part`仅作用于当前主题及公共对象。调整其他主题先明确select；不允许直接修改私有themes内部结构。受控颜色/来源更新写controlValues，原始默认值不变。
- 新增普通或复合控件归当前主题；锁定对象不能被更新/删除/间接重置。整轮原子应用，失败保持原设计。

对话指纹包含主题与覆盖，主题切换后旧响应必须经现有身份检查丢弃。工程DTO和确定性生成使用有效主题背景，保留全部主题。

本阶段完成的是编辑器/AI背景覆盖与作用域；不因此宣称手表端新增背景颜色选项、原生菜单持久化交互或真机验收已完成。

## 原生数据来源稳定身份（Schema39/basic47）

来源选项使用共享 `sourceCode(sourceId)` 稳定数值，而不是当前列表下标；颜色/布尔类型不变。App Settings、手表菜单、恢复默认、原生读取和模型工程DTO共用 `controlSettingKey` / optionCodes。

数据来源的新属性键为 `Gfc_Source_<controlId>`；旧键 `Gfc_<controlId>`保留声明为迁移读取，默认-1。新键默认-1，应用首次读取时按旧项目冻结的legacySourceOptions解释旧数值，仅选仍可用来源；无旧值或来源已移除则应用合法默认。随后写入稳定码。以后重新排序不改变含义，未知/损坏稳定码回退默认且不重新解释为旧下标。

Schema38→39冻结该项目当前options为legacySourceOptions，随后保留该顺序。迁移无法恢复升级前已经丢失的历史顺序；若旧工程曾改变列表并重新编译而没有记录其部署顺序，需维护者提供正确旧映射，不能声称凭数字推断原意。已有设置须与同一应用身份匹配；不生成通用.SET。

首次运行前新键为未初始化值，应用进入绘制/设置读取后才填入具体默认；不是使用-1作为实际来源。其他配置和主题键不变。

## 原生主题背景（basic51）

每个主题独立声明 `Gfc_Background_<themeCode(themeId)>` 数值属性（0..0xFFFFFF），App Settings和手表设置菜单共用键。网页背景覆盖成为编译初值；实际运行使用属性值，未知类型/越界回退编译值。AOD强制黑色，不沿用亮屏背景。菜单Background按当前主题列出编译值、原始预设色、黑色和内置调色板，修改后触发同一onSettingsChanged失效缓存和重绘。

当前主题重置写该主题原始背景色与原始控制默认值；不写其他主题或公共属性。stable themeCode不随主题重排或版本改变，因此保留设置。升级维持appId/themeId/controlId及类型时兼容值继续生效；删除的主题/控件旧属性不再读取，不执行全局Storage/Properties清空。未知主题码安全回退defaultId，来源已移除回退默认，损坏颜色/布尔类型也回退。不能用旧下标推断改变过顺序的来源。

本版没有自动覆盖用户项目的参考包升级；严格导入仍会报告损坏的浏览器项目定义，不静默删掉用户设计。未知引用必须先修复，导入失败保留原项目。主题版本号不构成自动替换布局的授权。

SDK编译与代码回归不等于手表设置入口、真实属性回调、重启持久化或防烧屏已实测；这些仍须单独记录。
