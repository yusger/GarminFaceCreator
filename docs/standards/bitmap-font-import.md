# 本地BMFont（FNT＋PNG）导入基线

首版为独立文字、时间、日期、数值字段使用固定目标像素字体。单页Unicode BMFont文本、8位灰度非交错PNG（与现有生成字形链一致）；FNT≤256KB、字符≤512、字偶距≤1024，图集≤512×2048/1MB，当前项目最多32份（普通目标最多8份；多主题目标最多16份，且每个主题的亮屏/AOD分别最多8份）且图集总量≤4MB。仅接受IHDR/IDAT/IEND三类PNG块，不接受压缩文本/色彩配置等附加元数据。检查页名、CRC、尺寸、字符索引、矩形、偏移、lineHeight/base、字偶距引用和授权，拒绝外部路径、多页/压缩打包、彩色或不透明RGBA图集。PNG解码必须成功，不悄悄回退系统字形。

字距按同一advance/kerning表逐字符排版，网页与原生使用同一指标；不假定SDK自动字偶距行为。原始描述、灰度图集、许可仅在浏览器保存，主动源码导出保留；编译只发准备好的FNT/PNG，AI只看到已批准字体身份、像素字号和字形范围。

固定图集不任意放大缩小；目标或亮屏/AOD字号不匹配须诊断并阻止本地生成，用户选择匹配图集或回到TTF/设备字体。初版不宣称复合内部字形、曲线文字、图表或多行排版支持。字形子集和资源预算需显示，完整字体被导入不等于全部占用都已适合设备。

该文档在代码/SDK/原生截图完成前是实施契约，不作为已支持声明。后续证据单独记录。依据[Garmin Resources / Fonts](https://developer.garmin.com/connect-iq/articles/core-topics/Resources.html)及[自定义字体说明](https://developer.garmin.com/connect-iq/connect-iq-faq/how-do-i-use-custom-fonts/)。

原生指标首版仅核验 Venu 4 45mm/41mm；其他目标明确阻止生成。SDK 9.3 两尺寸截图测得 drawText 顶部有1px内边距，受管绘制器做相应补偿；这是已测设备/SDK的映射，不能推断其他固件。生成FNT扩大字形自身advance容纳右侧外伸墨迹，整体排版仍由原始advance/kerning决定。后续升级SDK须重跑截图，不能仅靠编译通过。


## 目标像素排版（Schema47）

独立文字、时间、日期、数据可设置 `bitmapTracking`（整数0–12目标像素）、`bitmapTabular`（布尔）、`bitmapBaselineShift`（整数-64–64目标像素）、`bitmapLineHeight`（0用字体原值，或不小于字体原始行高且至多512的整数）。默认值维持已有布局；这些值不按454设计坐标缩放，也不缩放字形。

等宽数字要求有效的0–9字形，以这十个原始advance的最大值作为数字字格，数字居中字格；数字相邻的字偶距禁用，其他文字字偶距保留。字距仅加在字符之间。基线来自FNT的base，偏移和行高参与同一物理像素布局。基线对齐限位图文字；批量字体与排版保留位置、颜色、数据绑定，锁定或缺字使整批失败。切换到其他字体时清理不适用的位图排版项。

浏览器和本地生成使用共享度量规则。原生调用 `GfcBitmapText.drawDetailed(dc,x,y,w,h,font,id,text,align,tracking,tabular,baselineShift,lineHeight)`；旧的 `draw` 签名保留，等效于四项默认值。AI工程契约提供明确的方法和参数，不得把高级字距/等宽要求交给整串系统drawText。

最大读数检查对位图使用真实advance、字偶距和样本缺字检查；其他字体仍标网页估算。样本不改变实际读数，也不证明所有可能的数值均能放下。原生高级排版截图与默认指标校准分开验收；Schema47实现时默认指标沿用阶段133，新增参数的原生视觉校准仍待完成。


## 从授权TTF/OTF创建固定像素字体

字体库的“转为固定像素字体”入口对项目本地字体和内置授权字体使用相同链路；选择6–200的目标物理像素字号和可选附加字形。强制包含控件各可选数据源所需字符以及0–9，缺字拒绝，不使用浏览器备用字体。最多512个可见BMP字符；现有图集、字体份数及项目预算不变。

转换将原始完整许可和来源写入位图字体资产，生成独立的GFCBitmap内部字体名。原始项目字体保留，未自动上传；转换结果可直接使用字距、等宽数字、基线和行高工具。仅开放已核验Venu4两尺寸的独立文字/时间/日期/数据，锁定或复合内部不能转换。更换设备仍需匹配物理字号，不能默认为图集缩放。原生排版证据见[三字体对照](../research/bitmap-typography-validation.md)。


## 多设备字体覆盖（Schema48）

同一项目的设备变体可以独立选择注册TTF/OTF、设备字体、位图字体及字距/等宽数字/基线/行高；共享主设计保留原绑定，未覆盖属性继续继承。字体资源仍位于项目公共资产表，不复制进每个变体。存储最多32份位图字体以支持不同尺寸；普通单目标最多8份，多主题目标合计最多16份且各主题亮屏/AOD分别最多8份；总图集4MB不变，未用资产不进入当前目标的编译资源。

设备覆盖中的null表示清除继承的可选字体字段，解析为实际Layer时恢复undefined；例如从主设计TTF改为设备BMF时必须清除customFont，从BMF改回系统字体必须清除bitmapFontId及排版参数。普通几何不允许null。注册字体需匹配库或项目的id/family/file，位图引用和排版仍由共享验证器检查。Schema47升级只提升版本，不改既有身份/字节。

固定像素字体不会因切换型号自动缩放。为新目标选择或转换匹配的字号，或选择同一图集并调整该设备的设计字号。恢复设备默认会恢复共享绑定，若其物理字号不适用，生成仍须明确阻止；不以系统替代字形掩盖失配。编辑器预览、保存重开、导出再导入与复制沿用同一解析规则。AI公开字体操作仍限定共享主设计，设备微调通过字体库完成；不据此声明设备范围AI已开放。


三主题字体准备将不同像素字号作为不同资源组，角色按物理字号显式拆分，原始TTF/OTF及完整许可仍保留。转换以实际网页字形测得的整数基线偏移保持原位置，不改图层几何；这不等于原生截图通过。冻结的theme-project-v1仍保留项目16份/目标8份上限，旧提交合同不随编辑器预算变化而扩展。多设备共享主设计采用454像素字体，其他尺寸的精确字形属于设备覆盖；切换设备后请在设备微调范围预览和生成，不能把主设计的固定位图资源任意缩放。
