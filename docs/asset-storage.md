# 浏览器图片独立存储

IndexedDB 数据库升级为 v2，新增 assets 与 assetRefs。项目记录、设计快照和新代码快照只存储图片引用；编辑器加载时解析图片，JSON 备份仍内嵌图片以便独立迁移，源码 ZIP/编译使用去重后的实际资源。

assets 记录保存唯一图片数据，assetRefs 记录项目对素材的存活引用（包含设计/代码历史）。匹配先按哈希候选检索，再比较完整内容，不把非加密哈希当作唯一可靠身份。同一数据共享存储，相同候选哈希的不同数据不会互相覆盖。

项目保存、storageVersion 校验、素材写入、引用更新和回收处于同一读写事务。配额或事务失败全部回滚，内存设计保留。旧内嵌图片在版本升级事务内迁移，失败时旧数据库仍可恢复，不先删除原始数据。

回收查询实际引用索引，不仅依赖缓存 refCount；删除 A 项目不会破坏 B 的图片。设计与代码历史均计入引用。编辑中的图片及撤销状态在内存中保留完整数据，保存时按内容重新确认引用；未提交的导入不会先写入孤立资源。老代码快照没有历史素材字段时不会凭空恢复已丢失的素材，新快照包含资源清单及内容引用。

历史数量/元数据空间上限与图片存储分开计算，不在每个快照中重复计入同一图片。图片总空间仍受浏览器配额约束；配额失败提供导出与重试，不静默删除活跃项目。

## 基线与复测

同一测试场景：独立浏览器内建立三个相同 ClownWatch 参考副本，不涉及用户项目。

| 指标 | 内嵌存储 | 独立存储 |
| --- | --- | --- |
| 项目记录序列化体积 | 6,242,960 字节 | 383,468 字节 |
| 全部项目与素材/引用序列化体积 | 6,242,960 字节 | 2,337,367 字节 |
| 实际唯一图片数据 | 约 1.95MB，多份重复 | 1 份，3 个项目引用 |
| 项目记录单次写入样本 | 约 7.9–10.1ms | 约 0.9–1.7ms |

序列化总体积减少约 63%。写入样本只测 IndexedDB 项目记录写入，未计入素材查找、哈希、界面和防抖，不能当作整个自动保存流程的耗时。数据是本次测试样本，不保证所有浏览器/设备相同。
